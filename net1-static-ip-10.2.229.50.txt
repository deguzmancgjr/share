Configure static IP 10.2.229.50/24 on net1 (VM 108 - Node2Guacamole)
=====================================================================

These commands run INSIDE VM 108 (Proxmox UI -> VM 108 -> Console),
not on the node2 host. VM 108 is Ubuntu Server 24.04 with netplan.

NIC mapping (by MAC):
  bc:24:11:63:39:26 -> net1 / mgmt (vmbr0)
  bc:24:11:a5:3e:82 -> net0 / lab  (vmbr1)

Target:
  Address:     10.2.229.50/24
  Gateway:     10.2.229.1
  DNS:         10.2.196.11, 10.2.196.12
  Search:      ad.phl-imcite.net
  DNS record:  guac.ad.phl-imcite.net -> 10.2.229.50 (optional, recommended)


1. PRE-FLIGHT CHECKS
-------------------

Confirm .50 is free (from node2):
  nmap -sn -PR 10.2.229.50
  ip neigh show 10.2.229.50

Ask the campus DHCP/DNS owner to exclude 10.2.229.50 from the DHCP pool,
or use a reservation. ICMP silence is NOT proof it is free.

Log into VM 108 console and inventory:
  ip -br link
  ip -br addr
  ip route
  ls -l /etc/netplan/
  sudo netplan get

Map the NICs by MAC:
  bc:24:11:63:39:26 -> net1 / mgmt (vmbr0)
  bc:24:11:a5:3e:82 -> net0 / lab  (vmbr1)

Check whether cloud-init owns the network config:
  dpkg -l | grep -i cloud-init
  head -5 /etc/netplan/*.yaml

If a file says "generated by cloud-init", disable cloud-init networking
before editing:
  sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg >/dev/null <<'EOF'
  network: {config: disabled}
  EOF

Save the current routes (to preserve any lab routes):
  ip route > /root/routes-before.txt


2. BACK UP NETPLAN
------------------

  sudo tar czf /root/netplan-backup-$(date +%F-%H%M).tgz /etc/netplan
  sudo netplan get > /root/netplan-get-$(date +%F-%H%M).yaml


3. EDIT THE EXISTING NETPLAN FILE
---------------------------------

Use the file shown by ls /etc/netplan/ (commonly 00-installer-config.yaml
or 50-cloud-init.yaml):

  sudo nano /etc/netplan/00-installer-config.yaml

Important: replace the existing stanza for the mgmt NIC; do not leave two
definitions for the same MAC. If you prefer MAC matching, this is the
target shape (indent with spaces, never tabs):

network:
  version: 2
  renderer: networkd
  ethernets:
    lab:
      match:
        macaddress: "bc:24:11:a5:3e:82"
      dhcp4: true
      dhcp4-overrides:
        use-routes: false
      optional: true

    mgmt:
      match:
        macaddress: "bc:24:11:63:39:26"
      dhcp4: false
      dhcp6: false
      accept-ra: false
      addresses:
        - 10.2.229.50/24
      routes:
        - to: default
          via: 10.2.229.1
          metric: 100
      nameservers:
        addresses: [10.2.196.11, 10.2.196.12]
        search: [ad.phl-imcite.net]

Notes:
  - use-routes: false on the lab NIC prevents its DHCP from installing a
    competing default route. If the lab currently provides non-default
    routes you need, copy them from /root/routes-before.txt into the lab
    stanza as explicit routes entries.
  - If the existing file uses interface names (e.g. ens19) instead of
    MACs, keep those keys and only change dhcp4/addresses/routes/
    nameservers.
  - YAML must use spaces, never tabs. Two-space indentation.


4. VALIDATE AND APPLY SAFELY
----------------------------

  sudo chmod 600 /etc/netplan/*.yaml
  sudo netplan generate
  sudo netplan try

netplan try applies the config and auto-reverts after 120 seconds unless
you press Enter to confirm. Keep the Proxmox console open. If the console
session drops, wait for the rollback.

After confirming:
  sudo netplan apply


5. VERIFY INSIDE THE VM
-----------------------

  ip -br addr show
  ip route show default
  ping -c3 10.2.229.1
  ping -c3 10.2.196.11
  resolvectl status
  getent hosts node2.ad.phl-imcite.net

Expected: 10.2.229.50/24 on the mgmt NIC, one default route via
10.2.229.1, DNS working.

Test outbound internet:
  curl -sI https://tailscale.com | head -1


6. VERIFY FROM NODE2 AND YOUR PC
--------------------------------

From node2:
  ping -c3 10.2.229.50
  ip neigh show 10.2.229.50

The neighbor entry should show bc:24:11:63:39:26.

From your Windows PC 10.2.228.134 (PowerShell):
  ping 10.2.229.50
  Test-NetConnection 10.2.229.50 -Port 22

443 will only answer once Guacamole/nginx is configured.


7. DNS (RECOMMENDED)
--------------------

Add an internal A record on 10.2.196.11 / 10.2.196.12:

  guac.ad.phl-imcite.net  A  10.2.229.50

Then verify from the VM:
  getent hosts guac.ad.phl-imcite.net


8. TROUBLESHOOTING / ROLLBACK
-----------------------------

If something breaks, the Proxmox console still works:
  sudo ip -br a
  sudo ip r
  sudo journalctl -u systemd-networkd -e

Restore:
  sudo tar xzf /root/netplan-backup-YYYY-MM-DD-HHMM.tgz -C /
  sudo netplan apply

Common causes:
  - Wrong MAC/interface -> ip -br link
  - Duplicate default route -> ip route show default; adjust metric or
    use-routes
  - YAML error -> sudo netplan generate prints the line
  - No ARP reply from the PC -> check the switch/VLAN and that net1 is
    still on vmbr0
  - Guest firewall blocking -> sudo ufw status (allow 10.2.228.0/24 later,
    not yet)

No Proxmox-side change is needed: net1 is already attached to vmbr0.
